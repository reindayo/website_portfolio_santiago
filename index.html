Selected Work

Two Flagship Project Case Studies

Project 1

FCU Horizon Integrated Payment Gateway (FOCUS-PAY)

GitHub Repository

The Problem

Fragmented university fee payment workflows between student information systems, finance ledgers, and local e-wallets created manual reconciliation delays and duplicate-charge risks.

System Architecture & Tech Stack Justification

Event-driven integration architecture connecting FOCUS-SIS, the finance ledger, and e-payment APIs (GCash, Maya, online banking) using REST APIs, RabbitMQ message queues for asynchronous reliability, idempotency keys, and payload encryption.

Individual Contributions

Designed end-to-end integration workflows, API payload security/idempotency mitigations, and technical system documentation.

Measurable Results & Testing Outcomes

Validated zero duplicate ledger entries under simulated retry/timeout edge cases and mapped complete subsystem data flow across 9 architectural specifications.

Project 2

Capiz Bay Aquaculture & Seafood Supply (CBASS)

GitHub Repository

The Problem

Local seafood distributors across Capiz municipalities lacked batch-level traceability, leading to stock discrepancies and unmonitored cold-chain shelf life.

System Architecture & Tech Stack Justification

Normalized 6-table PostgreSQL relational database (suppliers, products, supply_batches, customers, orders, order_items) chosen over flat spreadsheets to enforce ACID compliance, foreign-key cascade rules, and batch-level expiration tracking.

Individual Contributions

Architected the ERD, wrote the DDL schema, populated multi-municipality test datasets, and authored analytical SQL join queries for inventory and order auditing.

Measurable Results & Testing Outcomes

Passed all referential integrity, cascade-delete, and multi-table join verification checks across 6 normalized tables.

SOP-01

Deterministic AI-Assisted Development & Anti-Hallucination Workflow

  1. Define bounded context: Provide explicit goals, constraints, file scope, and non-goals before generation to prevent fabricated assumptions.
  2. Apply custom SKILL.md rules: Enforce reusable instructions for code style, verification discipline, and domain-specific guardrails.
  3. Require evidence-based outputs: Demand citations to inspected files, command results, or data sources for claims that affect implementation.
  4. Run verification checks: Validate structure, logic, and requirements with deterministic checks (searches, tests, schema constraints, or manual review gates).
  5. Document decisions: Record assumptions, outcomes, and unresolved risks so generated work remains auditable and maintainable.
